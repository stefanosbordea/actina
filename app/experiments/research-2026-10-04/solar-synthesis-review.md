# Solar forecasting: synthesis, physics and small-data correction

4 October 2026. Research note, not a trained model or a reported gain. Six primary papers, with the inspected access level stated below. Mechanisms proposed for Aktina are adaptations, not reproductions of those papers.

Subsequent work: the fixed conditional-residual prototype was implemented in [experiment 004](../f1-004/README.md), followed by a [satellite-reference check](../reference-sensitivity-001/README.md). Its scale uses solar geometry, not an atmospheric clear-sky model. The proposal below is retained as the pre-experiment research rationale; measured outcomes and limitations are in the [research summary](../README.md).

**Best next experiment:** conditional historical residual scenarios around a fixed archived weather forecast. Add known solar geometry, retain a simple mean/bias-correction control, and test whether probabilities and intervals improve decisions on chronological validation. Synthetic rows can regularize a model or describe uncertainty; they do not create new observed weather or a fresh test set. Treat “parthenogenesis” as an analogy for generating training examples, not an established solar-forecasting method. [Rematerialization](https://arxiv.org/abs/2006.09616) concerns recomputing intermediate values to save memory; it supplies no missing weather information.

## Concrete experiment proposal

This is a modest adaptation to test, **not a novelty claim or an implemented result**. It builds on the existing archived-NWP controls rather than relabeling them as new work.

1. Freeze forecast origin, target hour, lead, issue cutoff, weather model/version, units and interval conventions. Keep hourly averages aligned with hourly clear-sky averages. Admit a historical target to the library only after it would have been available at the new origin.
2. Let `q` be archived NWP GHI and `c` a clear-sky reference for that target interval. On training data calculate `e=(y-q)/c` only above a fixed, preregistered low-sun guard. Keep low-sun intervals as a separate branch. Do not divide by nearly zero or silently discard them from evaluation.
3. Match a small set of earlier residuals using origin-available forecast cloud/GHI, solar elevation, season and lead. Use training-only scaling. Compare uniform neighbors with a simple distance weighting; do not start with a large learned generator. Retain a plain unnormalized residual analogue control to isolate normalization’s effect.
4. Form scenarios `max(0, q_target + c_target * e_neighbor)`. Enforce zero only for intervals wholly at night under the chosen geometry/interval definition. **Do not cap GHI at clear-sky irradiance:** clear-sky is a reference, not an absolute cloud-enhancement ceiling. [pvlib's clear-sky-index documentation](https://pvlib-python.readthedocs.io/en/stable/reference/generated/pvlib.irradiance.clearsky_index.html) explicitly permits over-irradiance. Inspect physically implausible scenarios rather than clipping away difficult cases after seeing scores.
5. Report empirical quantiles and the weighted fraction strictly above **600 W/m²**. Neighbor count is not a count of independent observations. For full-day scenarios, resample coherent historical residual blocks; independent hour shuffling would destroy cloud persistence and ramps.

If synthetic training is later attempted, compare real-only, real plus block-resampled residuals, and any learned generator under the same learner and compute budget. Fit generators/teachers inside each chronological training fold. Record source-day IDs, weights, seeds and real/synthetic counts; keep original observations. Teacher pseudo-labels never become test truth. Select augmentation weight, neighbor count and probability cutoff using validation only.

## Baselines and acceptance

- Yesterday-at-target-hour persistence; clear-sky-adjusted persistence with the same low-sun guard; fixed archived NWP; training-only constant/hour-conditioned NWP bias correction; low-capacity ridge residual correction; unchanged original model; same learner without synthetic inputs. Solar geometry alone adds predictable seasonality, not cloud information.
- Use rolling chronological validation with the 24-hour label boundary purge and availability checks. Freeze selection before scoring a genuinely new holdout. Already-inspected test periods remain exploratory. Include every retained hour; daylight/season/cloud-regime slices supplement the full denominator.
- Score MAE, RMSE and bias; Brier score and reliability for probabilities; interval coverage **and width**; precision, recall, F1 and confusion counts for `actual > 600`. Predeclare a precision/recall or false-alarm constraint so a model predicting almost no positive hours cannot win by precision alone. Report paired day-block uncertainty and runtime. Show any precision–recall tradeoff rather than an all-metric improvement claim.
- Confirm independent truth. Root `data/download_weather_data.py:5` requests the unpinned Open-Meteo historical archive; `data/features.py:8` shifts its radiation as the target. Open-Meteo describes this archive as weather-model/reanalysis data, not a local pyranometer record. Agreement between archived forecasts and related model-derived targets can reflect shared model structure. It establishes skill against that retained reference, not independent physical accuracy. A sensor or independently sourced measurement period is needed for that claim. [Historical archive documentation](https://open-meteo.com/en/docs/historical-weather-api), [fixed-lead forecast archive documentation](https://open-meteo.com/en/docs/previous-runs-api).

No models trained, original sources modified, dependencies installed, test forecasts selected, or external messages sent by this review. The next deliverable should be a frozen validation-only protocol and saved predictions, with acceptance criteria agreed before a new holdout is opened.

## Appendix: TabPFN considered, not run

**Hollmann et al., Nature (8 January 2025), [Accurate predictions on small data with a tabular foundation model](https://www.nature.com/articles/s41586-024-08328-6).** TabPFN learns a prediction algorithm by pretraining across synthetic tasks sampled from a designed prior, then conditions on a new dataset's labeled examples. This is synthetic-prior meta-learning: it does not turn generated Paphos values into observed ground truth. The paper evaluates small-to-medium tabular datasets, including settings up to 10,000 samples and 500 features. It motivates a pinned pretrained comparator; it does not establish solar, chronological or operating-cost superiority. Publisher abstract and method excerpts were inspected.

**Hoo et al., [From Tables to Time: Extending TabPFN-v2 to Time Series Forecasting](https://arxiv.org/abs/2501.02945v4).** First submitted January 2025; the inspected v4 is dated 26 January 2026. TabPFN-TS turns forecasting into tabular regression using temporal features and the pretrained v2 model, without time-series-specific pretraining. It supports covariates, so target-time solar geometry and genuinely origin-available NWP are plausible inputs. This is an adaptation to test, not proof that the prior captures Cyprus weather. The paper reports difficulty extrapolating outside the context target range. Its inference comparison reports roughly 30 times the single-GPU-equivalent time of the compared forecasting models. No local runtime or accuracy result exists here.

**Implementation gate:** review the exact checkpoint's code and weight licenses, commercial/distillation conditions, package versions, download size, telemetry and local peak memory before installing anything. Pin the v2 checkpoint if evaluating these papers; today's package default is not necessarily their model. The [official repository](https://github.com/PriorLabs/TabPFN) recommends GPU resources and distinguishes supported sizes by version; [release notes](https://github.com/PriorLabs/TabPFN/blob/main/CHANGELOG.md) document changed model licenses. Software and weight permissions must be checked separately. Do not assume a cloud service or upload is needed. If tested, keep the same chronological folds, target availability, original real targets and matched-hour baselines as the residual experiment; include preprocessing and inference costs. No package, checkpoint, account, license acceptance or cloud transfer was performed.
